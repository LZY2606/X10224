# 热转折案 · DSC 基线、相变积分与扫描历史审阅器

材料组把加热与冷却 DSC 序列放进同一份样品履历，为玻璃化、结晶与熔融事件
建立可重算的基线与积分。技术栈：Java 17 · Javalin · SQLite · SVG。

## 运行

```bash
./gradlew build -x test                                   # 依赖安装与编译
./gradlew test                                            # 核心规则与存储层测试
./gradlew run --args='--host 127.0.0.1 --port 5343'       # 启动演示
# 打开 http://127.0.0.1:5343
```

页面顶部内置九十秒样例路径：加载案例包 → 重放场景 → 拖动 ev-melt 区间 →
并排切换基线候选 → 解决分支冲突 → 点击旧事件回看当时的依赖版本与结论。

## 领域语义（机器可读地守护）

- 吸放热方向只来自仪器头元数据（exo-convention），绝不从文件名猜测；
  缺失时产生 `DIRECTION_UNKNOWN` 阻断诊断，保留全部合法候选。
- 加热段与冷却段按温度斜率符号切分，事件绑定单一分段，永不混用。
- 每个事件保留 LINEAR / TANGENT / SIGMOIDAL 并列基线，选择不删除候选。
- 样品质量修订使所有按质量归一化的派生过期（依赖图传播，仅重算受影响子图）。
- 空区间只产生 `EMPTY_INTERVAL` 诊断，不伪造焓值；无法转换的原始行留在
  原位置并附 `UNIT_UNCONVERTIBLE` 诊断。

## 存储与一致性

- 仪器输出、样品质量、扫描速率、气氛、温度标定、用户切线分别存档、各自版本化。
- 每次推导产生独立版本，写入日志（write_journal）完成后才切换当前指针；
  写入中断后重启只见旧版本或完整新版本。
- 两人从同一版本保存产生可解决冲突（branches 表），未选分支保留。
- 事件日志为机器可读判断依据；导出、删除本地库、再导入后身份/顺序/来源保持。

## 案例包（src/main/resources/casepack）

`instrument_output.csv`（非等间隔温度、热-冷-热循环、反向热流伪迹、
重叠熔融肩峰、不可转换行）+ 质量/扫描速率/气氛/标定/切线 JSON +
`scenario.json`：参数修订 → 局部源改动 → 冲突人工决定 → 质量修订。

## 测试（仅使用仓库内 fixture）

反向热流、非等间隔温度、重叠转折、循环段切换、质量版本变更、并列基线、
空区间、写入中断、旧版本迁移、并发保存、案例包重放、导出再导入身份保持。
